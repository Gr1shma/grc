# grc

A terminal-based todo manager backed by a plain Markdown file.

> [!WARNING]
> This project is heavily generated by LLM/AI. If you are uncomfortable with AI-generated code, please review the source carefully before use.

## Install

```sh
# Clone the repository
git clone https://github.com/Gr1shma/grc.git
cd grc

# Install the binary
cargo install --path .
```

## Usage

```sh
# Open the default file (~/.todo.md)
grc

# Open a specific todo file
grc /path/to/todo.md
```

By default, `grc` reads and writes `~/.todo.md`. You can specify a file path as an argument or override the default path with the `GRC_TODO_PATH` environment variable:

```sh
GRC_TODO_PATH=/path/to/todo.md grc
```

## Interface

```
╭ Sections ───────╮╭ Work ─────────────────────────────────────────────╮
│▌▾ Work       1/5││▌□ Ship release                              today │
│ │   Urgent   0/2││ ✓ Write docs                                      │
│   Home       0/1││ □ Plan next week                      Mar 1, 2027 │
│                 ││ □ Urgent › Fix bug                            tmr │
│                 ││ □ Urgent › Call back                              │
╰─────────────────╯╰───────────────────────────────────────────────────╯
 j/k move  ·  x toggle  ·  a/o add  ·  i edit  ·  t due  ·  ? help
 NORMAL                                                    1/6  todo.md
```

The left panel is the section tree; the right panel shows the selected section's
tasks, including tasks from its subsections (marked with a `›` breadcrumb). A
focused panel has an accent border and bold title. The bottom two lines are a
context-sensitive hint bar and a status bar. The status bar shows the mode pill, a
transient message (`saved`, `pasted`, errors), overall progress, and the file
name. A message clears itself after about three seconds, or as soon as the next
key is pressed. Due dates are right-aligned and coloured by urgency; completed tasks are
dimmed and struck through. A scrollbar appears at the panel's right edge only
when its content overflows. Long task text is cut with `…` before the due
column, and a row that is too narrow for its `Section ›` breadcrumb drops the
breadcrumb rather than the task text.

### Selection and colour

The selected row is a dark tint a shade lighter than the panel, plus a `▌` bar in
the left gutter; the unfocused panel uses a weaker tint. Every foreground colour
is chosen against the background it can land on and checked in the test suite for
at least a 4.5:1 contrast ratio (3:1 for decorative glyphs such as the tree
guides), so dim metadata stays readable under the bar.

By default `grc` does not paint a background: the terminal's own shows through,
so a transparent or translucent terminal profile keeps working. The selection
bar and popups are always painted, because text on them has to be readable
whatever is behind it. Set `GRC_BG=1` to fill the canvas with the dark panel
colour instead, `NO_COLOR=1` to drop all colour and inherit the terminal's, and
`GRC_ASCII=1` for ASCII checkboxes (`[ ]` / `[x]`), fold markers (`>` / `v`),
and scrollbars. Without colour the selected row is marked by the `▌` gutter bar
and bold text. None of these change the file format.

Colour depth follows `COLORTERM`: with `COLORTERM=truecolor` (or `24bit`) `grc`
uses its own RGB palette, and otherwise it falls back to the sixteen named ANSI
colours, where the selection bar is `DarkGray` carrying black text. Coloured
accents are chosen against a dark background, so on a light terminal set
`NO_COLOR=1` (inherit the terminal's colours) or `GRC_BG=1` (use the tested dark
canvas).

Checkboxes use `□` and `✓` rather than `☐` and `☑`: the ballot-box pair is in
the emoji set, and a terminal that draws it with an emoji font makes that line
taller than the rest, which breaks the grid. Every glyph in the interface is one
cell wide and outside the emoji set.

## Keybindings

Press `?` in the app for the same list, grouped as Navigate / Sections / Tasks /
Dates / Misc, so the section keys and the task keys are each listed together
rather than interleaved.
A count prefix applies to `j`/`k` motions and to multi-task `dd`; other commands
ignore it.

### Global

| Key | Action |
|-----|--------|
| `j` / `k` (or `↓` / `↑`) | Move down / up in the focused panel |
| `5j` / `3k` | Move five down / three up |
| `gg` / `G` | Jump to top / bottom |
| `H` | Hide or show completed tasks |
| `u` / `Ctrl-r` | Undo / redo (bounded to 100 document snapshots) |
| `/` | Open the live filter |
| `Esc` | Clear the filter when one is set |
| `?` | Open the help overlay; close it with `?`, `Esc`, or `q` |
| `q` / `Ctrl-c` | Save and quit |

### Sections panel (left)

| Key | Action |
|-----|--------|
| `l` / `Enter` / `Tab` | Focus the task panel |
| `a` | New child section under the selected one |
| `A` | New section above the selected section's parent (same as `O` for top-level sections) |
| `o` / `O` | New section at the same level below / above |
| `i` | Rename the selected section |
| `dd` | Delete the section and its subtree |
| `yy` / `p` / `P` | Yank section / paste below / paste above |
| `J` / `K` | Move the section down / up among its siblings |
| `za` / `zM` / `zR` | Toggle fold / fold all / unfold all |
| `]d` | Jump to the next overdue task in the file and focus the task panel |

### Tasks panel (right)

| Key | Action |
|-----|--------|
| `h` / `Esc` / `Tab` | Return to the sections panel |
| `j` / `k` (or `↓` / `↑`) | Move down / up |
| `Space` / `x` / `Enter` | Toggle done |
| `a` / `o` / `O` / `A` | Add task below / below / above / append |
| `i` / `t` | Edit task text / edit due date |
| `dd` / `3dd` | Delete the selected task / three tasks starting at the cursor |
| `yy` / `p` / `P` | Yank task / paste below / paste above |
| `:` | Recursively sort the selected section by due date |
| `J` / `K` | Move the task down / up among its visible siblings |
| `]d` | Jump to the next overdue task in the file (wraps, skips completed; reveals it if a fold or the filter hides it) |
| `H` | Hide or show completed tasks |

`]d` looks through the whole file rather than the rows on screen. If the overdue
task is inside a folded section its ancestors are unfolded, and if the active
filter hides it the filter is cleared — the status bar says which of the two
happened. A filter that does not hide the target is left alone.

### Text inputs, filter, help, and conflict

| Key | Action |
|-----|--------|
| `Enter` / `Esc` | Confirm / cancel a text input |
| `←` / `→`, `Home` / `End` | Move the text cursor |
| `Ctrl-a` / `Ctrl-e` | Move to start / end of input |
| `Backspace` / `Delete` | Delete before / at the cursor |
| type, `Backspace`, `Enter`, `Esc` | Filter prompt: append, delete, apply, clear |
| `j` / `k`, `Esc` / `q` / `?` | Scroll / close the help overlay |
| `r` / `o` | On an external-change conflict: reload / overwrite |

The filter is an append-only prompt: `Backspace` removes the last character.
Text inputs (task, section, due date) use the full cursor editor above, and in
all of them `Enter` on an empty field closes the editor: for a task or a section
that cancels the input (the status bar says why), and for a due date it clears
the date. `Esc` always cancels.
When editing a task, a parseable `due:` token is highlighted and its resolved
date previewed inline; an invalid token is shown in red and never clears the
existing date. With a filter set, `Esc` clears the filter before it returns to
the sections panel.

### Mouse

Mouse capture is always on. The wheel moves the selection in the focused panel
(it scrolls the help overlay while that is open), and a left click focuses the
clicked panel and selects the row under the cursor, honouring any scrolling.
Clicking outside the help overlay closes it.

## Due Date Shortcuts

When setting a due date with `t`, you can type any of:

| Input | Resolves to |
|-------|-------------|
| `YYYY-MM-DD` | Exact date, e.g. `2025-12-31` |
| `YYYY/MM/DD` `YYYY.MM.DD` | Exact date with a different separator |
| `today` `tod` `t` | Today |
| `tomorrow` `tmr` `tmw` `tom` | Tomorrow |
| `next week` `nextweek` `nw` | 7 days from today |
| `sun`/`mon`/.../`sat` | Strictly next occurrence of that weekday (also full names) |
| `next mon` `next monday` | Strictly future occurrence (same as a bare weekday) |
| `this monday` | That weekday today if it is today, otherwise the next occurrence |
| `+3d` `-2d` `+2w` `+1m` `+1y` | Relative offset (days/weeks/calendar months/years) |
| `in 3 days` `in 2 weeks` | Relative offset (also months/years) |
| `jun 15` `june 15` | Month name + day (current year, next year if passed) |

Weekday edge cases are deliberate:

- A bare weekday is always strictly in the future. On a Monday, `mon` means the following Monday.
- `this monday` includes today, so on a Monday it means today.
- `next monday` is always in the future, so on a Monday it means the following Monday.

Leave the due-date field empty and press `Enter` to clear the date. Invalid input shows an error and keeps the existing date; it never clears it.

You can also embed a due date inline when creating or renaming a task (press `a`/`o`/`i`). Type the task text followed by ` due:` and any of the shortcuts above, and the date is parsed automatically while the `due:` token is stripped from the task text:

```
Submit report due:2025-06-15
Buy milk due:next monday
Call mom due:in 3 days
Pay rent due:2025/06/15
```

Only a parseable date is removed. Unrecognized `due:` text is left as part of the task.

## Sorting

`:`, in the task panel, recursively sorts every task in the selected section and its subsections. Within each section the stable order is:

1. undone tasks before completed tasks;
2. earlier due dates before later ones;
3. tasks without a due date last.

## Saving and external changes

Every document change is written immediately with an atomic replace, and `q` saves once more before leaving. If the todo path is a symlink, `grc` writes to the link target and never replaces the symlink itself.

Before each save, `grc` compares the file's modification time and length with the last load/save. If another program changed the file, `grc` does not overwrite it silently: the status bar shows a conflict and:

- `r` reloads the file from disk (discarding in-memory changes);
- `o` overwrites the file with the in-memory document.

Save errors and conflicts appear in the status bar instead of closing the terminal. Quitting retries the save.

Tasks before the first heading are preserved in the Markdown file but are not editable in the TUI; when present, the status bar reports how many there are.

## File Format

Plain Markdown — edit it directly in any editor. Lines that `grc` does not recognize (prose, comments, blank lines) are preserved when the file is saved.

```markdown
# work

- [ ] Fix bug
- [x] Write tests due:2025-06-15

## backend

- [ ] Deploy API

### api

- [ ] Fix endpoint
```
